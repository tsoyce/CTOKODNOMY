# CTOKODNOMY

«100 к 1» для вашего мероприятия.

Веб-приложение для игры в зале: гости смотрят общее табло, участники предлагают ответы со своих телефонов, капитан отправляет итоговый вариант, ведущий управляет раундами. Можно играть и с устными ответами.

React + TypeScript, Node.js 24 + Fastify, PostgreSQL (проверены версии 14 и 17). Сервер хранит состояние партии и проверяет права каждого действия; публичное табло не получает скрытые ответы. WebSocket сообщает об изменениях, после чего каждый экран запрашивает разрешённые ему данные.

## Что есть в приложении

- Главная мероприятия, правила и помощь, вход ведущего и вход команды по приглашению.
- Защищённый первый запуск с одноразовым токеном и созданием администратора.
- Вопросы с очками, экспорт JSON и мастер импорта файла или текста с проверкой, предпросмотром и подтверждением замены; учебный пример и запрос для внешнего ИИ.
- Пульт ведущего, табло гостей, интерфейс участника и капитана.
- Свои названия, заголовок главной, подписи, логотипы организатора, игры и партнёров; значок сайта, цветовые темы и предпросмотр главной, табло и телефона.
- Загрузка PNG/JPEG/WebP до 2 МБ при установке и в админке.
- Сохранение партии, перехват после ошибок, пауза и исправление решения ведущего.
- Светлая контрастная тема «Проектор» и отдельное переключение контраста на табло, удобные действия ведущего и команды на телефоне.
- Повтор игры с нулевым счётом и новыми приглашениями, удаление партии с подтверждением.
- Инфографика ответов после раунда и отдельная страница итогов, которую организатор публикует для гостей после игры.
- Проверки правил, API и браузерного сценария; сборка для Node.js в BrainyCP и альтернативное размещение Docker.

Демонстрационные вопросы показывают работу интерфейса; это не результаты социологического опроса. Перед мероприятием подготовьте собственные вопросы и проведите репетицию с реальными устройствами и сетью площадки.

Короткий сценарий подготовки, показа статистики и повторной игры — в [памятке ведущему](docs/GAME_GUIDE.md). В **«Вопросы → Импорт JSON»** загрузите файл до 3 МиБ или вставьте готовый JSON от внешнего ИИ, проверьте набор и сохраните его. [Формат и подготовка данных опроса](docs/SURVEY_IMPORT.md) описаны отдельно; прямого подключения к Яндекс Анкетам и встроенного ИИ нет.

## Запуск для разработки

Нужны Node.js **24**, npm и PostgreSQL **17**. Для БД можно использовать Docker с Compose v2. Команды ниже выполняются из папки репозитория в терминале; на Windows используйте PowerShell, WSL или Docker Desktop в режиме Linux containers.

1. Создайте локальные настройки из примера:

   ```sh
   cp .env.example .env
   ```

   В PowerShell вместо `cp` можно выполнить `Copy-Item .env.example .env`. Файл `.env` исключён из Git. Замените пример пароля в `POSTGRES_PASSWORD` и в `DATABASE_URL` одинаковым значением. Для пароля удобно использовать случайную строку из шестнадцатеричных символов, чтобы не требовалось URL-кодирование.

2. Если PostgreSQL ещё нет, запустите отдельную **локальную** БД:

   ```sh
   docker run --name ctokodnomy-dev-db --env-file .env -p 127.0.0.1:5432:5432 -v ctokodnomy-dev-pgdata:/var/lib/postgresql/data -d postgres:17-alpine
   ```

   Если контейнер уже создан, используйте `docker start ctokodnomy-dev-db`. Порт `5432` должен быть свободен. При другом порте измените и проброс, и `DATABASE_URL`. Существующий PostgreSQL также подходит: создайте для проекта отдельную БД и пользователя.

3. Установите зависимости и подготовьте первый вход:

   ```sh
   npm ci
   npm run db:migrate
   npm run setup:token
   npm run dev
   ```

4. Откройте **http://localhost:5173**: при первом запуске автоматически откроется установщик. Введите полученный токен и создайте администратора с паролем от 1 до 128 символов. На следующем шаге задайте свои надписи, загрузите логотипы и выберите оформление. Токен является секретом: его не нужно добавлять в Git или отправлять в чат. После завершения установки мастер закрывается.

`npm run dev` запускает сервер на `3000` и Vite на `5173`. Открывайте браузер по адресу из `APP_ORIGIN`. Для телефона в одной сети задайте адрес компьютера, например `APP_ORIGIN=http://192.168.1.10:5173`, и `HOST=0.0.0.0`; разрешите доступ только в доверенной локальной сети.

Для просмотра производственной сборки вне Docker:

```sh
npm run build
```

Затем задайте в локальном `.env` `APP_ORIGIN=http://localhost:3000` и запустите `npm start`. В рабочем размещении используется HTTPS. Для Node.js-приложения в BrainyCP смотрите [BRAINYCP.md](docs/BRAINYCP.md), для Docker — [DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Проверки

Для проверок API и браузера нужна **отдельная тестовая база**, которую можно очищать. Не указывайте базу действующего мероприятия. Например, для локального контейнера:

```sh
docker exec ctokodnomy-dev-db createdb -U ctokodnomy ctokodnomy_test
```

Добавьте `DATABASE_URL_TEST` с адресом этой базы в локальный `.env`. Затем:

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Playwright запускает собственный собранный сервер на `127.0.0.1:4173`, использует `DATABASE_URL_TEST` и создаёт отдельную схему на каждый запуск. Сервер разработки на `3000` можно оставить работающим. Если `4173` занят, задайте свободный порт через `E2E_PORT`, например `E2E_PORT=4174 npm run test:e2e` в Bash или `$env:E2E_PORT="4174"; npm run test:e2e` в PowerShell. Изменять адрес БД разработки не требуется. CI выполняет проверки с PostgreSQL и Chromium автоматически при push и pull request.

## Cloud Codex

Обычная задача использует существующий checkout; отдельный Git worktree не нужен. В этой облачной среде кэш npm размещается в доступной для записи папке:

```sh
npm ci --cache /workspace/.cache/npm
```

Параметры БД и доступность Chromium зависят от среды. Когда Chromium уже установлен системой, задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium` для браузерных проверок. Не сохраняйте учётные данные в инструкции запуска.

Если среда использует свой сетевой proxy и доверенный CA, Docker-сборке нужны уже предоставленные средой настройки. Dockerfile поддерживает необязательный BuildKit secret `custom_ca`; сертификат используется только при установке зависимостей и не попадает в образ. Команда для такой облачной среды:

```bash
read -r docker_proxy_host docker_proxy_ip < <(node --input-type=module -e 'import {lookup} from "node:dns/promises"; const host=new URL(process.env.HTTPS_PROXY).hostname; const {address}=await lookup(host,{family:4}); console.log(host+" "+address)')
DOCKER_CONFIG=/workspace/.cache/docker docker build --network=host --add-host "$docker_proxy_host:$docker_proxy_ip" --build-arg HTTP_PROXY --build-arg HTTPS_PROXY --build-arg NO_PROXY --secret "id=custom_ca,src=$NODE_EXTRA_CA_CERTS" -t ctokodnomy:local .
```

Используйте её только при наличии соответствующих переменных. Первая строка получает текущий адрес предоставленного proxy через DNS; `--add-host` нужен, если DNS внутри BuildKit не разрешает это имя. На обычном сервере достаточно `docker compose build`. Проверка TLS и контрольные суммы npm остаются включены.
