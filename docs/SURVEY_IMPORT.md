# Опрос → подготовка через ИИ → вопросы для игры

В админке откройте **«Вопросы → Импорт JSON»** (`/admin/questions/import`). Мастер принимает готовый JSON файлом или текстом, показывает ошибки и предпросмотр до сохранения. Здесь же можно скачать учебный пример и скопировать запрос для внешнего ИИ.

Рабочий сценарий: выгрузить опрос из Яндекс Анкет → подготовить агрегированный набор через внешнего ИИ → проверить его в мастере → сохранить вопросы. Приложение не читает сырые CSV-анкеты, не подключается напрямую к Яндекс Анкетам и не обращается к ИИ: преобразование выполняется вне игры.

## Как подготовить данные

1. Сохраните исходную выгрузку и условия опроса: вопрос, дату, число ответивших, один или несколько вариантов допускались.
2. Если человек перечислил несколько вариантов, учитывайте **первый выбранный ответ по смыслу**. «Голову, ручку» даёт один ответ «голову». При этом «телефон не беру, беру воду» даёт «воду»: механически брать первое слово или разрезать по запятой нельзя. Неясный случай проверьте по исходнику, отметьте в `notes`, не угадывайте.
3. Сведите ответы в группы. Объединяйте только действительно одинаковые по смыслу варианты; сохраняйте правила группировки и проверяйте, что количества не потеряны и не продублированы. В `answers` оставьте **все группы**, включая единичные ответы. Не обрезайте список до шести и не пересчитывайте сумму к 100.
4. Проверьте публичные подписи `text`. Исходные фразы без имён и контактов можно оставить в приватном поле `originals`, синонимы для ведущего — в `aliases`, правила обработки — в `notes`. Для спорной шутки организатор выбирает подходящую гостям подпись вручную. Автоматической цензуры в игре нет; простое добавление фразы в `originals` не скрывает такой же текст, если он остался в `text`.
5. Проверьте сформированный JSON в мастере и сохраните в библиотеку. При необходимости отредактируйте публичные подписи и порядок в библиотеке **до создания партии**. Экспорт позволит сохранить подготовленный набор в том же формате.

На игровое табло попадают **6 групп с наибольшими очками**. При одинаковых очках сохраняется их порядок в массиве `answers`. Если у 6-го и 7-го вариантов одинаковая частота, мастер предупредит о границе отбора: организатор может поменять порядок равных вариантов. Остальные группы сохраняются в полной статистике и облаке ответов, их частоты не пропадают. Для вопроса с меньшим числом групп табло показывает все имеющиеся.

`points` — игровой вес ответа, целое число. Это могут быть реальные частоты, если они укладываются в ограничения, либо веса по заранее выбранному правилу. Если нужны пересчёт или округление, согласуйте правило и сохраните его в `notes`; не выдавайте полученные очки за исходное число людей. `respondentCount` хранит именно число опрошенных, а не сумму очков.

Инфографика считает процент как `points / сумма points всех групп вопроса × 100`, включая ответы за пределами ТОП 6. Этот процент не равен доле респондентов. Облако показывает **группы ответов целиком**, с размером по их очкам; это не подсчёт отдельных слов в анкетах. Источник, дата и число опрошенных показываются, когда известны; неизвестные сведения не нужно придумывать. Учебные и вымышленные наборы помечаются `isDemo:true`.

Исходную выгрузку храните отдельно: `originals` помогает сверять формулировки, но не заменяет полный архив анкет. Это до 100 исходных фраз на группу, а не список людей или способ вычисления частоты. Поля `originals`, `aliases` и `notes` доступны организатору и в административном экспорте; гостям и участникам их не передают. Экспорт с исходными фразами предназначен для организатора, его не следует публиковать как файл с итогами.

## Как пользоваться мастером

1. Нажмите **«Выбрать JSON-файл»** или вставьте ответ внешнего ИИ в поле **«Готовый JSON»**. Нужен JSON без Markdown-ограждений. Размер файла или текста в UTF-8 — не более **3 МиБ (3 145 728 байт)**.
   В поле **«Название набора»** задайте общее название для всех вопросов файла. Например, «Опрос гостей — октябрь». Можно подставить имя файла отдельной кнопкой. Пустое поле сохранит названия `pack` из самого JSON; менять формат файла не требуется.
2. Нажмите **«Проверить вопросы»**. Проверка пока ничего не сохраняет. При ошибках раздел **«Исправьте ошибки»** укажет вопрос, ответ и поле, например «Вопрос 2 → ответ 3 → очки». Исправьте исходный JSON и повторите проверку.
3. Просмотрите все вопросы, варианты и очки, источники, сведения об опросе и пометки учебных данных. Первые шесть ответов помечены **«ТОП 6 · табло»**, остальные — **«Статистика»**. Отдельно показаны сумма очков табло и сумма всего опроса. Исходные фразы раскрываются только в этом административном предпросмотре. Проверьте подписи для гостей и предупреждения о равных частотах.
4. Если UUID совпадают с вопросами библиотеки, выберите **«Обновить совпадающие»** и явно отметьте **«Заменить совпадающие вопросы в библиотеке»**. Либо выберите **«Добавить все как новые»**, чтобы сохранить отдельные копии без изменения прежних вопросов.
5. Нажмите **«Сохранить вопросы»**. Сервер повторно проверит весь набор и сохранит его одной транзакцией. Только после успешного сохранения вопросы окажутся в библиотеке.

Изменение исходного JSON сбрасывает прежний предпросмотр: перед сохранением нужно проверить новый текст. Клиент и сервер используют одну схему проверки. Снимки вопросов уже созданных партий не меняются при обновлении библиотеки.

Если библиотека изменилась и при сохранении появилось новое совпадение UUID, мастер попросит повторить проверку и заново выбрать, какие вопросы заменить. Весь набор останется несохранённым до разрешения конфликта; незаметной замены нового совпадения не произойдёт. Формат JSON-файла для этого менять не нужно.

**«Скачать пример JSON»** даёт готовый учебный набор с условными числами и `isDemo:true`. **«Скопировать запрос для ИИ»** копирует инструкции для использования во внешнем сервисе; данные опроса автоматически никуда не отправляются.

Изменение названия после проверки отменяет предпросмотр и подтверждение замены: снова нажмите **«Проверить вопросы»**. Исходный JSON при этом остаётся в поле.

## Наборы и массовые действия

В библиотеке **«Вопросы»** карточки наборов показывают названия и количество вопросов. Нажмите карточку, чтобы открыть её вопросы; у именованного набора есть действие **«Переименовать»**. Название можно задать и после импорта: отметьте вопросы, выберите новый набор и нажмите **«В набор»**.

Отметки позволяют перенести несколько вопросов в существующий или новый набор, убрать их из набора либо удалить. **«Выбрать все показанные»** учитывает текущий поиск и фильтры. Массовые действия применяются только к отмеченным вопросам, которые сейчас видны; скрытые отмеченные вопросы сохраняют выбор, их количество указано рядом. Чтобы снять все отметки, нажмите **«Снять весь выбор»**. За одну операцию можно изменить до 500 вопросов. Удаление требует подтверждения с количеством вопросов.

Каждый вопрос входит в один набор. Одинаковое название объединяет вопросы, в том числе из разных импортов; для отдельного набора используйте другое название. Набор исчезает из списка, когда в нём больше нет вопросов. Переименование в уже занятое название отклоняется: для объединения перенесите вопросы в нужный набор. Эти действия меняют библиотеку; вопросы в уже созданных партиях сохраняются.

При создании игры выберите название и нажмите **«Выбрать набор целиком»**, чтобы получить готовый список раундов. Подробности — в [памятке ведущему](GAME_GUIDE.md).

## Формат файла

Сохраните JSON в UTF-8. Пример ниже целиком учебный: числа условные, реального опроса за ними нет. Его можно скопировать и импортировать для проверки.

```json
{
  "format": "ctokodnomy-questions-v1",
  "questions": [
    {
      "prompt": "Учебный пример: что берут с собой на прогулку?",
      "answers": [
        {
          "text": "Воду",
          "points": 40,
          "aliases": ["Бутылку воды"],
          "originals": ["Водичку", "Бутылку воды"]
        },
        {
          "text": "Телефон",
          "points": 20,
          "aliases": ["Смартфон"]
        },
        { "text": "Хорошее настроение", "points": 10, "aliases": [] },
        { "text": "Ключи", "points": 8, "aliases": [] },
        { "text": "Зонт", "points": 7, "aliases": [] },
        { "text": "Наушники", "points": 5, "aliases": [] },
        { "text": "Перекус", "points": 3, "aliases": [] },
        { "text": "Фотоаппарат", "points": 2, "aliases": [] }
      ],
      "source": "Учебный пример, реальный опрос не проводился",
      "surveyDate": "",
      "respondentCount": null,
      "notes": "Вымышленные ответы и условные очки. На табло — 6 самых популярных групп, в статистике — все 8. Исходные формулировки — примеры словоупотребления, а не полный список анкет.",
      "isDemo": true,
      "pack": "Проверка импорта"
    }
  ]
}
```

| Поле | Ограничение |
| --- | --- |
| `format` | Ровно `ctokodnomy-questions-v1` |
| Размер JSON в UTF-8 | До 3 МиБ (3 145 728 байт), для файла и вставленного текста |
| `questions` | От 1 до 500 вопросов в одном импорте |
| `prompt` | От 1 до 500 символов после удаления пробелов по краям |
| `answers` | От 1 до 500 групп, включая редкие; тексты не повторяются без учёта регистра |
| `answers[].text` | От 1 до 200 символов; публичная подпись группы для табло и статистики |
| `answers[].points` | Целое число от 0 до 1000 |
| `answers[].aliases` | Необязательно; до 30 непустых строк по 1–200 символов, по умолчанию `[]` |
| `answers[].originals` | Необязательно; до 100 непустых исходных фраз по 1–500 символов, только для организатора |
| `source` | До 1000 символов, неизвестный источник — `""` |
| `surveyDate` | До 40 символов; для известной даты удобно `YYYY-MM-DD`, неизвестная — `""` |
| `respondentCount` | Целое число от 1 до 1 000 000 либо `null`, если неизвестно |
| `notes` | До 4000 символов; подсказки ведущему и правила преобразования, гостям не передаются |
| `isDemo` | `true` для учебных или вымышленных данных, иначе `false` |
| `pack` | До 100 символов, название набора для библиотеки |
| `id` у вопроса и ответа | Необязательный UUID. Для нового набора можно пропустить; при проверке приводится к нижнему регистру |

Все сведения после `answers` необязательны: строки по умолчанию пустые, `respondentCount:null`, `isDemo:false`. Поэтому учебный набор всегда явно помечайте. Старые файлы формата `ctokodnomy-questions-v1` без `originals` продолжают приниматься. Наборы с более чем 12 группами требуют версии приложения с поддержкой полного опроса; прежний сервер их не примет. Обновление приложения и загрузка подготовленного файла выполняются отдельно. Импорт проверяется целиком и сохраняется одной транзакцией: ошибочный вопрос не приводит к частичному сохранению файла. Если все вопросы и исходные формулировки не помещаются в 3 МиБ, разделите набор на несколько файлов, сохраняя полный список групп каждого вопроса.

Экспорт содержит UUID. В режиме **«Обновить совпадающие»** вопрос с существующим UUID заменяет соответствующий вопрос библиотеки; для этого мастер требует явное согласие. Неизвестный или пропущенный UUID создаёт новый вопрос. **«Добавить все как новые»** создаёт отдельные копии всех вопросов и ответов с новыми идентификаторами.

Повторный импорт без UUID создаст новые вопросы. При одинаковом `pack` они попадут в тот же именованный набор; чтобы получить отдельный набор, задайте другое название перед проверкой. Идентификаторы вопросов внутри одного файла и ответов внутри одного вопроса не должны повторяться; различие только в регистре букв не делает их разными UUID. Изменения библиотеки не меняют снимки уже созданных партий.

## Заготовка запроса для ИИ

Передайте вместе с запросом структуру JSON выше и выгрузку опроса без имён и контактов участников. Например:

> Подготовь вопросы для игры в JSON формата `ctokodnomy-questions-v1` по приложенному образцу. Используй только данные выгрузки: не выдумывай ответы, количества, число опрошенных, источник или дату. В составном ответе учитывай первый выбранный вариант по смыслу, а не первое слово: «голову, ручку» → «голову», «телефон не беру, беру воду» → «воду». Неоднозначные случаи и группировки сначала покажи для проверки. Сохрани все группы, включая единичные, и исходные частоты: на табло игра сама выберет ТОП 6, в статистику попадут все. При равных частотах важен порядок `answers`; отдельно покажи равенство на границе 6-го и 7-го мест. Не пересчитывай сумму к 100. Не смешивай число людей с количеством ответов. Неизвестное число респондентов — `null`, неизвестные дата и источник — пустые строки. `text` — публичная подпись: для спорных шуток предложи нейтральную формулировку с сохранением смысла и покажи замены организатору перед финальным JSON. Исходные фразы без имён и контактов запиши в необязательный `originals` (до 100 непустых фраз по 1–500 символов на группу), синонимы — в `aliases` (до 30 по 1–200 символов), методику — в `notes` (до 4000 символов). `originals` не определяет частоту и не публикуется гостям. В вопросе от 1 до 500 групп, `text` до 200 символов, очки — целые числа 0–1000. Если нужен пересчёт, сначала предложи правило. Для новых вопросов и ответов не добавляй `id`. Реальные данные помечай `isDemo:false`, вымышленные учебные — `true`. После согласования выдай только валидный JSON без Markdown. В одном файле 1–500 вопросов, размер в UTF-8 до 3 МиБ; при необходимости разбей набор на файлы без удаления групп.

Организатор сверяет результат с исходной выгрузкой и предпросмотром до сохранения. Дальнейшая автоматизация должна сохранять происхождение данных и проверяемые количества.
