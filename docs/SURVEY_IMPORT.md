# Опрос → подготовка через ИИ → вопросы для игры

Импорт и экспорт вопросов JSON уже работают в админке, в разделе **«Вопросы»**. План следующего этапа: выгружать опрос из Яндекс Анкет, готовить агрегированный набор через внешнего ИИ, проверять его и загружать в игру. Прямого подключения к Яндекс Анкетам и встроенного преобразования сырых анкет пока нет.

## Как подготовить данные

1. Сохраните исходную выгрузку и условия опроса: вопрос, дату, число ответивших, один или несколько вариантов допускались.
2. Сведите ответы в группы. Объединяйте только действительно одинаковые по смыслу варианты; сохраняйте правила группировки и проверяйте, что количества не потеряны и не продублированы.
3. Выберите игровые варианты и их очки. Если опрос допускает несколько ответов, сумма частот может быть больше числа респондентов. Если на табло попала только часть вариантов, их сумма тоже не описывает весь опрос.
4. Проверьте сформированный JSON, импортируйте его в библиотеку и просмотрите вопросы перед созданием партии. Экспорт позволит сохранить подготовленный набор в том же формате.

`points` — игровой вес ответа, целое число. Это могут быть реальные частоты, если они укладываются в ограничения, либо веса по заранее выбранному правилу. Если нужны пересчёт или округление, согласуйте правило и сохраните его в `notes`; не выдавайте полученные очки за исходное число людей. `respondentCount` хранит именно число опрошенных, а не сумму очков.

Инфографика считает процент как `points / сумма points показанных вариантов × 100`. Этот процент не равен доле респондентов. Источник, дата и число опрошенных показываются, когда известны; неизвестные сведения не нужно придумывать. Учебные и вымышленные наборы помечаются `isDemo:true`.

## Формат файла

Сохраните JSON в UTF-8. Пример ниже целиком учебный: числа условные, реального опроса за ними нет. Его можно скопировать и импортировать для проверки.

```json
{
  "format": "ctokodnomy-questions-v1",
  "questions": [
    {
      "prompt": "Учебный пример: что берут с собой на прогулку?",
      "answers": [
        {
          "text": "Воду",
          "points": 40,
          "aliases": ["Бутылку воды"]
        },
        {
          "text": "Телефон",
          "points": 20,
          "aliases": ["Смартфон"]
        }
      ],
      "source": "Учебный пример, реальный опрос не проводился",
      "surveyDate": "",
      "respondentCount": null,
      "notes": "Условные очки для проверки импорта и диаграммы.",
      "isDemo": true,
      "pack": "Проверка импорта"
    }
  ]
}
```

| Поле | Ограничение |
| --- | --- |
| `format` | Ровно `ctokodnomy-questions-v1` |
| `questions` | От 1 до 500 вопросов в одном импорте |
| `prompt` | От 1 до 500 символов после удаления пробелов по краям |
| `answers` | От 1 до 12 вариантов; тексты не повторяются без учёта регистра |
| `answers[].text` | От 1 до 200 символов |
| `answers[].points` | Целое число от 0 до 1000 |
| `answers[].aliases` | Необязательно; до 30 непустых строк по 1–200 символов, по умолчанию `[]` |
| `source` | До 1000 символов, неизвестный источник — `""` |
| `surveyDate` | До 40 символов; для известной даты удобно `YYYY-MM-DD`, неизвестная — `""` |
| `respondentCount` | Целое число от 1 до 1 000 000 либо `null`, если неизвестно |
| `notes` | До 4000 символов; подсказки ведущему и правила преобразования, гостям не передаются |
| `isDemo` | `true` для учебных или вымышленных данных, иначе `false` |
| `pack` | До 100 символов, название набора для библиотеки |
| `id` у вопроса и ответа | Необязательный UUID. Для нового набора можно пропустить |

Все сведения после `answers` необязательны: строки по умолчанию пустые, `respondentCount:null`, `isDemo:false`. Поэтому учебный набор всегда явно помечайте. Импорт проверяется целиком и сохраняется одной транзакцией: ошибочный вопрос не приводит к частичному сохранению файла.

Экспорт содержит UUID. **Импорт вопроса с существующим UUID обновляет его в библиотеке**, без UUID создаёт новый. Повторный импорт файла без UUID создаст ещё один набор. Идентификаторы вопросов внутри одного файла и ответов внутри одного вопроса не должны повторяться. Изменения библиотеки не меняют снимки уже созданных партий.

## Заготовка запроса для ИИ

Передайте вместе с запросом структуру JSON выше и выгрузку опроса без имён и контактов участников. Например:

> Подготовь вопросы для игры в JSON формата `ctokodnomy-questions-v1` по приложенному образцу. Используй только данные выгрузки: не выдумывай ответы, количества, число опрошенных, источник или дату. Объединяй смысловые повторы только после явного описания групп и проверки частот. Если решение об объединении неоднозначно, сначала задай вопрос. Не смешивай число людей с количеством выбранных ими ответов. Неизвестное число респондентов — `null`, неизвестные дата и источник — пустые строки. Сохрани исходные количества; если ограничения игры требуют выбора вариантов или пересчёта, сначала предложи правило и дождись моего решения. В одном вопросе не более 12 вариантов, очки — целые числа 0–1000. Синонимы запиши в `aliases`, методику — в `notes`. Для новых вопросов и ответов не добавляй `id`. Реальные данные помечай `isDemo:false`, вымышленные учебные — `true`. После согласования выдай только валидный JSON без Markdown.

Организатор сверяет результат с исходной выгрузкой до импорта. Следующий этап автоматизации должен упростить эту проверку и сохранить происхождение данных, а не заменять её вымышленными «популярными ответами».
