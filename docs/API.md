# Контракт API

Все пути начинаются с `/api`. Ответы JSON. Ошибки `{message: string, code?: string}` с соответствующим HTTP-статусом. Авторизация через HttpOnly cookies, все изменяющие запросы проверяют Origin при его наличии. Типы: `shared/types.ts`.

- `GET /site` → SiteInfo (только публичные сведения).
- `GET /me` → Me.
- `POST /setup` `{token,username,password,brand}` → Me; после инициализации 409. Токен создаётся CLI и имеет срок жизни.
- `POST /setup/media` multipart поле `file`, заголовок `x-setup-token` → `{url}`; загрузка логотипа с действующим кодом до завершения установки. Загрузка не погашает код. Неверный или истёкший код — 403, завершённая установка — 409.
- `POST /login` `{username,password}` → Me; `POST /logout` → `{ok:true}`.
- `POST /account/password` `{currentPassword,newPassword}` → `{ok:true}`.
- `GET /settings` → Brand (admin); `PUT /settings` Brand → Brand.
- `POST /media` multipart поле `file` → `{url}` (admin). PNG/JPEG/WebP, не более 2 MB; сигнатура проверяется.
- `GET /questions` → Question[] (admin); `POST /questions` Question без обязательного id → Question.
- `POST /questions/demo` → `{count}` (admin): добавляет три явно помеченных демонстрационных вопроса. Их ответы находятся только на сервере, а не в клиентской сборке.
- `PUT /questions/:id` Question → Question; `DELETE /questions/:id` → `{ok:true}`.
- `GET /questions/export` → `{format:'ctokodnomy-questions-v1',questions:Question[]}`.
- `POST /questions/import` `{format:'ctokodnomy-questions-v1',questions:Question[],replaceIds?:string[]}` → `{count}` (admin); JSON до 3 МиБ, весь набор проверяется и сохраняется атомарно. Клиентский предпросмотр не вызывает этот запрос и не заменяет серверную проверку.
- `POST /questions/batch` `{action:'move',ids:string[],pack:string}` или `{action:'delete',ids:string[]}` → `{count}` (admin): перенос в набор либо удаление 1–500 вопросов. `pack` до 100 символов; точное существующее имя сохраняется, у нового обрезаются пробелы по краям, пустая строка убирает из набора. UUID приводятся к нижнему регистру, повторы отклоняются с 400. Если хотя бы один вопрос отсутствует, ответ 404 и весь запрос откатывается.
- `POST /questions/packs/rename` `{from:string,to:string}` → `{count,pack}` (admin): `from` — точное прежнее название, `to` — новое непустое имя до 100 символов после обрезки пробелов. Нет исходного набора — 404; имя занято другим набором — 409 с `PACK_EXISTS`; неизменное имя допустимо. Все вопросы набора переименовываются одной транзакцией.
- `POST /games` `{title,questionIds:string[],teams:[{name,color},{name,color}],rules?:Rules}` → HostGame; снимок вопросов и бренда.
- `GET /games/:id/public` → PublicGame; `GET /games/:id/host` → HostGame (admin).
- `GET /games/:id/team` → TeamGame (participant в этой партии).
- `POST /games/:id/reset` `{requestId,revision}` → HostGame (admin): та же партия возвращается в лобби, счёт и результаты очищаются, оформление берётся из текущих настроек сайта. Название, команды, правила и снимок вопросов сохраняются; участники и прежние приглашения больше не действуют. Повтор того же requestId не выполняет сброс ещё раз; revision не возвращается к нулю.
- `DELETE /games/:id` `{revision}` → `{ok:true}` (admin): удаляет партию, участников и историю её команд. Библиотека вопросов остаётся. Несовпадение revision — 409.
- `POST /games/:id/results/publication` `{published:boolean,revision}` → HostGame (admin): публикует или скрывает страницу итогов; публикация разрешена только для завершённой игры. Изменение видимости увеличивает revision, повтор с уже действующим значением не меняет состояние.
- `GET /games/:id/results` → PublicGameResults: для завершённой игры администратор видит предпросмотр; остальные — только явно опубликованные итоги. До завершения или без права просмотра — 404.
- `POST /join` `{code,name}` → `{gameId,participant:Participant}`; код относится к конкретной команде. Создаёт cookie участника.
- `POST /games/:id/commands` CommandRequest → HostGame (admin).
- `POST /games/:id/captain` `{participantId}` → HostGame (admin); снимает роль с прежнего капитана этой команды.
- `POST /games/:id/suggest` `{text,requestId,revision}` → TeamGame (участник команды хода).
- `POST /games/:id/submit` `{text,requestId,revision}` → TeamGame (капитан команды хода).
- `GET /ws/games/:id` WebSocket отправляет только `{type:'changed',revision:number}`. Клиент после события запрашивает своё представление. Секретное состояние через WS не передаётся. Доступ публичный, поскольку событие не содержит текстов, кодов и ответов.
- `GET /health` → `{ok:true}` после проверки подключения к БД; вне API — `/health` также доступен.

Повторный requestId не повторяет действие. Несовпадение revision — 409; клиент обновляет состояние и показывает сообщение. Номер revision и применение команды меняются атомарно с сохранением БД. Набор демовопросов помечается isDemo, добавляется только по явному действию администратора; реальным опросом не называется.

Команда ведущего `{type:"statistics-view",view:"list"|"cloud"}` передаётся в обычном `CommandRequest` с `requestId` и `revision`. Допускается после завершённого текущего раунда либо в завершённой партии со сыгранными раундами; очки и открытия не меняет. `PublicGame.statisticsView` возвращает выбранный вид. Табло применяет его в статистике после раунда; финальный экран остаётся экраном победителей. Команда сохраняется в истории и отменяется через `undo`; старые сохранения и сброс партии получают `"list"`.

Пароль администратора при установке, смене и восстановлении содержит 1–128 символов. Пустой пароль не принимается.

Brand содержит `title`, `organizer`, `description`, `heroTitle`, `heroNote`, `footerText`, четыре цвета и ссылки на изображения. `heroTitle` — заголовок главной, `heroNote` — подпись под кнопками, `footerText` — текст внизу главной и табло; пустые подписи скрываются. Для старых сохранённых настроек недостающие поля получают стандартные значения. Оформление текущей партии сохраняется в её снимке.

`PublicGame.roundStats` содержит все ответы текущего вопроса только после завершения раунда; во время розыгрыша значение `null`, а закрытые варианты остаются скрытыми. В `PublicRoundStats` передаются текст и очки ответов, отметка об открытии в игре, источник, дата опроса, число респондентов, признак демоданных и результат раунда. `share` — процент от суммы очков вариантов этого вопроса, а не доля респондентов. При нулевой сумме все доли нулевые. Множитель раунда не меняет эти доли.

`PublicGameResults.rounds` включает сыгранные раунды; начатый, но досрочно остановленный раунд помечается `completed:false` и не получает начисленных очков. Будущие вопросы, заметки ведущему, синонимы, приглашения и данные участников отсутствуют. `resultsAvailable` в публичном состоянии и списке игр означает, что итоговая страница доступна гостям. Сброс игры отзывает публикацию; отмена завершения тоже закрывает итоги, если возвращает игру к розыгрышу.

Точный формат вопроса, ограничения и пример импортируемого JSON — в [SURVEY_IMPORT.md](SURVEY_IMPORT.md). Схема в `shared/questionImport.ts` общая для клиента и сервера. UUID приводятся к нижнему регистру; повторяющиеся UUID вопросов в одном наборе или ответов внутри одного вопроса отклоняются, включая различия только в регистре.

Без `replaceIds` контракт сохраняет прежнюю семантику: существующий UUID обновляет вопрос библиотеки, неизвестный или пропущенный создаёт новый. Мастер `/admin/questions/import` перед отправкой требует подтверждения замены совпадающих вопросов и передаёт их UUID в `replaceIds` (до 500 UUID); для новых вопросов и копий передаёт пустой список. В режиме «Добавить все как новые» клиент назначает новым копиям новые UUID; отдельного серверного режима для этого нет.

При наличии `replaceIds` сервер разрешает замену только перечисленных вопросов. Если между предпросмотром и сохранением возникло новое совпадение UUID с отличающимся содержимым, весь импорт откатывается с 409 и кодом `IMPORT_CONFLICT`; мастер предлагает повторить проверку библиотеки. Совпадение UUID с полностью идентичным содержимым разрешено для повторной отправки. `replaceIds` — поле API-запроса мастера, формат файлов `ctokodnomy-questions-v1` не меняется. Снимки уже созданных партий не меняются.

Наборы определяются существующим полем `Question.pack`; одинаковые строки обозначают один набор, пустая — вопросы без набора. Мастер импорта может заменить `pack` всех вопросов указанным пользователем названием перед отправкой, без изменения формата файла. Новые вопросы сохраняют порядок файла; обновление существующих не меняет их прежнюю позицию в библиотеке. Массовый перенос и переименование изменяют только `pack`, остальные данные сохраняются. Все записи библиотеки сериализуются короткой блокировкой таблицы; обычное чтение не блокируется. Игровые снимки независимы от библиотеки и сохраняются после переименования, переноса и удаления вопросов.
